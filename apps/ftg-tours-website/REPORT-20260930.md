## 0. 最終根因：技能書的碼位表整組錯位（2026-09-30 追加）

這是全部混戰的源頭，且**仍在生產中自我傳播**。

技能書 `ftg-tours-brand-maintain` v0.6.0 的品牌碼位表是**旋轉錯位**的：

| 技能書標示 | 該碼位的真實字 |
|---|---|
| 墾 ← U+587E | 塾 |
| 墳 ← U+58BE | **墾（正確品牌字）** |
| 塾 ← U+58FE | 壾（連候選名單都不是） |
| 墧 ← U+8FB7 | 辷 |

真值（Python `chr()` 實測）：

```
墾 U+58BE（正確）   塾 U+587E   墳 U+58B3   壾 U+58FE
聖 U+8056（禁用）   墺 U+58BA   墧 U+58A7   辷 U+8FB7   墎 U+588E
```

### 傳播鏈（這就是「漂移」不是隨機bug的原因）

1. 技能書寫入錯位表
2. `scripts/brand-codepoint-audit.cjs` 帶著 `RIGHT = 0x587e`（= 塾）發布
3. 任何人執行 `--fix`，**把全站正確的「墾」改寫成「塾」**
4. 再加上一個斷言「不含 0x587E」的測試，把錯誤釘死
5. 下一輪 session 讀技能書 → 看到「墾 = U+587E」→ 確認「塾是對的」→ 寫進 `home.test.jsx:9`
6. 回到第 3 步

最惡劣的一處是 `scripts/ftg-render-audit.mjs:47` 把 `0x58be`（**就是正確的「墾」**）列進 `BAD` 清單。該腳本會把正確品牌字判為違規。

### 已修（6 個檔案）

| 檔案 | 修正 |

| `scripts/ftg-render-audit.mjs` | `RIGHT`→0x58be；`BAD` 移除 0x58be、加入 0x587e/0x58b3 |

### 對防範的直接影響

- 「用視覺比對判斷 CJK」這條規矩**不夠**。真正的失效點是**碼位表本身寫錯**，而碼位表是人手抄的。

## 第一節：`pre_commit_gate.py` 的缺陷

### 1.1 根本原因

原始腳本判定「這是不是 TypeScript 測試檔」時，只比對副檔名白名單：

```
.py  .ts  .tsx  .pyi
```

`.js` / `.jsx` **不在清單內**。

於是在一個 React + JavaScript 專案（`ftg-tours-website`）裡：

1. 閘把 `.jsx` 測試檔判定為「非 TS」→ **跳過 TS 相關檢查**
2. 接著因為專案無 `.ts` 檔，進入「無 TS 檔則視為通過」分支 → 回報綠燈
3. 但同時走到「偵測不到 node_modules 視為依賴未安裝」分支 → 拋出 `FileNotFoundError`
   - 實測錯誤：`FileNotFoundError: [WinError 3] 'C:\Project\esggo\apps\oneringai\node_modules\@google\adk'`

**淨效果：閘在一個正常的 JS 專案上崩潰，而它崩潰這件事本身就是唯一的輸出——沒有任何有效的通過／不通過判定。**

### 1.2 為何這種缺陷特別危險

因為閘**看起來在工作**（有輸出、有 emoji、有分項結果），只是結論錯了。這比沒有閘更糟——沒有閘會讓人知道要人工檢查，壞掉的閘會讓人以為已經檢查過。

### 1.3 修法

| 修補 | 內容 |
|---|---|
| 修 A | 語言偵測改為**內容啟發式**：讀取檔案前 2KB，含 `import`/`from '`/`require(` 即判定為 JS/TS 家族 |
| 修 B | 副檔名白名單補上 `.js` / `.jsx` / `.mjs` / `.cjs` |
| 修 C | 依賴缺失改為**明確降級為警告**並列印實際嘗試的路徑，不再拋例外 |
| 修 D | 新增 `--allow-main` 參數，允許在主分支上執行 |

修後實測（`ftg-tours-website`）：**5/7 通過，耗時 1 秒**（修前為崩潰）。

### 1.4 迴歸測試

`C:/Users/dingj/.hermes/scripts/test_pre_commit_gate.py` — 7 個案例，自測 `exit=0`：

涵蓋：Python 專案、TS 專案、JSX 專案、無依賴環境、缺依賴環境、明確失敗情境、無語言相關情境。

## 第三節：網站四個問題的成因

### 3.1 為何 logo 的中文字「一植被取錯」

**成因：品牌名在程式碼中分裂成兩種寫法，且先前的判斷方向相反。**

| 位置 | 原字 | 次數 |
|---|---|---|
| 網頁本體（`index.html` SEO、`Navbar`/`Footer` 的 `alt`、`seo.js`、`translations.js`、所有頁面、測試） | 塾 | 113 |
| 分享卡 `public/og-image.svg` | **墾** | 42 |

**關鍵事實：`src/tests/home.test.jsx:9` 記載著先前的決定：**

```js
// 塾 = U+587E 是正確品牌字；墾 U+58BE / 壾 U+58FE / 聖 U+8056 都是歷史錯字。
// 這個 repo 長期在「墳趣」「塾趣」之間漂移過（見 skill P1/P54）
```

也就是說：**過去某一輪已經做過完全相同的判斷，並鎖定為「塾」，還寫了碼位測試防止再漂移。而 `og-image.svg` 當時被判為異常。**

2026-09-30 品牌主確認正確名稱為「**墾趣旅遊**」。因此：

- **我第一輪把 `og-image.svg` 當成「離群值 / 異常」來分析，方向完全相反——它其實是唯一寫對的那一份。**
- 這是本次報告中最重要的一項事實更正。

**次要成因**：`og-image.svg` 宣告 `font-family="'Noto Sans TC'"`，但網站從未載入 Noto Sans TC（`index.css:1` 只載入 Noto Serif TC），該 SVG 的中文必然 fallback 到系統字體，**外觀必定與網站本體不一致**。且 `og:image` 指向 `logo.webp`、JSON-LD 的 `image` 指向 `og-image.svg`，兩者不一致；多數社群平台不支援 SVG。

### 3.2 為何每次看樣式都不一樣

**根因：`src/index.css:1`**

```css
@import url('https://fonts.googleapis.com/css2?family=Inter:...&family=Noto+Serif+TC:...&display=swap');
```

四個疊加因素：

1. **`display=swap` 是「每次不一樣」的直接元凶。** 語意為「新字體未就緒時，先以系統字體渲染，就緒後替換」。網路快 → 直接見新字體；網路慢 → 先見系統字體再跳動。**每次可見結果可能不同。**
2. **字型不在自己的伺服器上。** 全站 70 張圖片中無任何字型檔（`.woff2`）。中文字型完全依賴 Google。本專案未改動，Google 側或網路環境改變即導致網站變樣。
3. **載入方式最劣。** CSS `@import` 需「下載 CSS → 解析 → 發現 import → 下載字型 CSS → 下載字型檔」，串行且阻塞。專案未設定 `preconnect`。
4. **讀者裝置差異。** 未安裝 Noto Serif TC 者直接使用系統預設字（macOS PingFang／Windows 微軟正黑體／Linux 另類），**同一網站在不同裝置外觀不同**。

### 3.3 為何網頁會崩壞

**先更正一個錯誤：** 我第一次掃描回報「7 張圖片損壞」，該結果**為誤報**——比對用的正則在檔名空格處截斷。重新驗證：**70 張全數存在，真實損壞 0 張。**

實際風險：

| 風險 | 說明 | 現況 |
|---|---|---|
| R1 | `@import` 位於 CSS 首行且指向外部主機。該主機不可達時，瀏覽器持續等待至逾時才放棄，其間畫面未套用樣式，呈現白畫面 | **最可能的崩壞成因** |
| R2 | 13 條圖片路徑含空格或全形斜線，如 `team day-頁首大橫幅.webp`、`成果內容-ESG／SDGs 對應整理.webp` | 現況正常，但為潛在脆弱點 |
| R3 | `og:image` 指向 `.svg`，多數社群平台不支援 | 分享預覽可能空白 |

### 3.4 部署後會不會再變動

**會。且「改了也不會變」同樣成立。**

線上實測（`curl -I`）：

```
/images/logo.webp  →  Cache-Control: max-age=14400     （4 小時）
                     cf-cache-status: REVALIDATED
```

| 項目 | 說明 |
|---|---|
| 持續變動來源 | 中文字型不在本機，於 Google 側。本專案未改動仍可能變化 |
| 變動滯後 | `max-age=14400` → 部署後最長 4 小時內訪客仍見舊版 |

**另一項發現：repo 內的 `ftgtours-nginx-fixed.conf` 與線上不一致。**

```
repo:  location /images/ { expires 48h; add_header Cache-Control "public, immutable"; }
線上:  Cache-Control: max-age=14400   （4 小時，無 immutable）
```

該設定檔**從未實際部署**，僅為 repo 內提案。此本身構成風險：`immutable` 語意為「告知瀏覽器此資源永不變更，無須回源驗證」。若日後套用，更換 logo 後訪客將在 48 小時內持續見到舊圖，且被明示不得更新。

**另一項無效設定：** `index.html` 內含

```html
<meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate" />
```

現代瀏覽器**全部忽略**此 meta 形式（IE 以外從未生效）。實際快取行為由伺服器決定，此三行等同無效。

## 第四節：我三次被自己的驗證工具誤導

**這是本次最具價值的發現。** 三次全部發生在我宣稱「已驗證」之後。

### 4.1 第一次：正則截斷 → 誤報 7 張圖片損壞

正則 `/images/[^"'`)\s]+` 排除了空白字元，導致 `team day-頁首大橫幅.webp` 被截斷為 `.../team` → 回報 404。
**實際損壞 0 張。**
教訓：比對用的抽取規則本身需要驗證，尤其當它回報大量「錯誤」時。

### 4.2 第二次：對二進位檔做文字比對 → 誤報 58 處品牌字殘留

`grep -ro "塾" dist/` 對 PNG/WebP 二進位內容掃描，隨機位元組序列命中 UTF-8 位元組，每檔恰好 1 次，且找不到「墾趣」→ 確認為雜訊。
**實際 `dist` 文字資產為 `塾=0`、`墾=54`。**
教訓：對二進位檔做文字比對的結果不可信；必須以位元組精確比對 + 交叉驗證（同時檢查正例與反例）。

### 4.3 第三次：只比對檔名 → 誤判「同一工具的兩份副本」

以 `find -name "pre_commit_gate*.py"` 找到兩個同名檔案，即判定為「同一工具的舊副本，可能修錯份」，未先比對內容。
實測：兩者為**完全不同工具**——一個 7 項（`~/.hermes/scripts/`）、一個 10 項（`AppData/Local/hermes/scripts/`），僅檔名相同。
教訓：檔名相同不等於內容相同。任何「這是副本」的推論都必須先驗證內容。

### 4.4 三者的共同根因

**在未驗證驗證工具的情況下，直接引用其輸出作為結論。**

這正是本專案 `pre_commit_gate.py` 原始缺陷的**同一類問題**——一個看起來在工作、實際結論錯誤的檢查器。**我在修掉閘的缺陷之後，自己又示範了同一個缺陷。**

## 第五節：防範對策

### 5.1 已落地的機制

| 機制 | 位置 | 作用 |
|---|---|---|
| 迴歸測試 | `.hermes/scripts/test_pre_commit_gate.py` | 語言偏誤不再可能回歸 |

### 5.2 應建立的一般規則

| # | 規則 | 對應本次 |
|---|---|---|
| R1 | **報告「發現 N 個問題」前，先確認 N 不為 0 的合理性。**大量錯誤通常代表檢查器有誤，而非專案有問題 | 4.1、4.2 |
| R2 | **對二進位檔不做文字比對。**需比對時用位元組精確比對，並同時驗證正例與反例 | 4.2 |
| R3 | **「這是副本」「這是同一個檔案」等推論，必須先比對內容。**檔名不足以支撐結論 | 4.3 |

### 5.6 快取策略：現況實測（未修改）

線上實測 `Server: cloudflare`、`cf-cache-status: HIT`、`Age: 92`、`Cache-Control: max-age=14400`。

工作區 `ftgtours-nginx-fixed.conf` 的規則是 `\.(js|css|...|woff2)$ → expires 4h + immutable`，但**線上回應並沒有 `immutable`**。兩者不一致，確認該檔不是線上實際載入的版本（或被 Cloudflare 覆寫）——這正是本節待辦第 5 項所指的問題。

該規則另有一處語意矛盾：同一條規則同時套用於 **檔名含雜湊**的 `/assets/*`（`immutable` 安全）與**檔名固定**的 `/fonts/*`、`/images/*`（`immutable` 宣稱永不重驗，但換檔後 4 小時內仍拿舊檔）。字型檔名目前不含雜湊，是日後換字型時最可能踩到的 stale-cache 路徑。

**建議修法**：`/assets/*` 保持 `immutable` + 長 max-age；`/fonts/*` 與 `/images/*` 改為短 max-age 且**不加 `immutable`**，或改用內容雜湊檔名。此項涉及 VPS 上的 nginx 設定，未經你同意不動。
